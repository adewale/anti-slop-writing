The dividing line is not easy-versus-hard, it's checkable-from-the-string versus checkable-only-from-context. Give the oracle any assertion whose answer is fixed the moment you see the text: does the literal string "it's worth noting that" appear, does a paragraph carry three em-dash insertions, do five sentences in a row land within two words of each other, does a bullet list repeat "**Bold Header:** sentence" four times running, does a sentence match the "Not X. Y." skeleton. None of these need to understand what the sentence means, only to count or match what it says. The doctrine's own headers already draw part of this line for you: phrases sit under "Avoid by default," words sit under "Words to review." A phrase like "it's worth noting that" carries almost no legitimate use, so the oracle can fail it outright. A word like "robust" is explicitly marked for review, which is the doctrine telling you, before any harness exists, that it needs a reader before it needs a verdict.

Everything the doctrine's false-positive restraint depends on has to stay with a judge, because that restraint is defined as reading past the flagged word into the sentence around it. Whether "robust" is earned turns on whether the paragraph already named an idempotency key, a retry receipt, and a dead-letter cutoff — a question about what one span of text proves about another, not about the word by itself. The staccato contrast test asks the same shape of question: is the second half of an antithesis backed by something the first half already showed, or does the rhythm assert a claim the evidence never made? A script can find every antithesis shaped like "not X, it's Y"; it cannot tell you whether X and Y are each already true of the surrounding paragraph. Copula displacement fails the same way for the opposite reason — "serves as" is fine when it introduces three named failure modes and empty when it doesn't, and only a reader who has seen what follows the verb can tell which sentence it is.

That gives the harness a concrete design rule for everything short of the phrase list: word-list hits and shape-matches — an antithesis, a hedge template, a copula construction — should leave the oracle as candidates, not verdicts. A hit is a hypothesis that a span is worth a judge's attention, the same posture the doctrine already asks a human editor to take toward their own detector hits. Skip that discipline in either direction and the harness fails in a specific, predictable way.

Lean too far toward the oracle and it starts grading vocabulary instead of prose. A frozen list fails in exactly the two ways the doctrine already warns about: it dings earned language it has no way to excuse, and it goes blind the moment usage moves on without it. The doctrine's own note about "delve" — a word that peaked in 2023-2024 output and, by 2025, had mostly dropped out of it — is the second failure already on record: a lint rule anchored to that word quietly stops catching anything current while it keeps fining the rare writer who reaches for it on purpose. An oracle that owns final verdicts, not just hit-lists, will flag the idempotency-key queue as slop forever, because nothing in a string match can read the dead-letter cutoff two clauses later.

Lean too far toward the judge and the harness loses the one thing a deterministic check is for: a stable answer to a question that never needed comprehension. Ask a judge whether "it's worth noting that" appears in the text and you've traded a guaranteed-correct grep for a probabilistic read that can catch the phrase on one run and miss it on the next, adding variance to a check that had none to begin with. That instability scales with the corpus: a regression suite where identical output can score differently on two separate runs is close to useless for telling whether a doctrine change actually helped, and every assertion routed through a judge adds latency and cost that a counter would not. The doctrine limits its own judge use to "one bounded judge-refine pass" rather than re-judging every line twice; the harness should keep that same discipline instead of routing every assertion through the expensive path by default.

The working split is oracle-for-counts and judge-for-claims: hand the script anything a grep or a tally can settle on its own, and hand the judge only the sentence whose verdict depends on what the paragraph around it already proved. A script can tell you a paragraph used "robust" three times; only a judge can tell you whether the dead-letter cutoff two clauses later earned it.
