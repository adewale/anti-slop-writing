# Design checks before generation

This is the maintainer's design check, not an independent evidence review.

- Installed base and all references are frozen at merged #22. Experimental patches
  change only their repo-only `SKILL.md` copies; neither changes installed doctrine.
- The #18 historical “40 cases” were repeats of one held-out target. The new compound
  panel is conservatively one family. Likewise the teaser, Twitter and highlighter
  panels each count as one source/scaffold family, not independent replications.
- All 69 standing writing/control cases are allocated in every doctrine arm. Standing
  one-trial outcomes are screening measurements, not reliable per-case failure rates.
- Six supplied-fact tune twins penalize indiscriminate asking/cutting. Pairs stay in
  one family. The supplied-definition compound case still permits criticism of other
  unsupported claims: a definition is not proof of an unlimited consistency guarantee.
- Historical highlighter tune assertions demanded invented mechanisms/findings. New
  grounded tune counterparts replace those demands; originals are preserved. Three
  historical holdouts are quarantined before generation rather than repaired from
  model outcomes. The earned-honesty holdout guard remains available.
- Historical holdouts are public and design-visible. No fresh-blind evidence or powered
  general improvement claim is possible from this allocation. Outcome-free simulations
  miss the 80% target; the single-family target gate has exact maximum power zero.
- Cross-family judges, factual/task co-primaries, diagnostics separation, blinded length
  counts, complete slot auditing and retained nulls use the repaired instrument.
- Software tests cover tampered/misassigned packages, no-skill package exposure, missing/
  extra/duplicate trials, score aggregation and one-family pseudoreplication. The new
  runner's test initially failed because the module did not exist; all 106 tests now
  pass. Package-boundary tests were added after the transport extension, not claimed as
  a separate red-first implementation. All seven repository gates pass, including
  pinned skills-ref validation, Ruff and 39 checked-in example gradings.

## Manual case check (not a model trial)

`evals/cases.md`, generic-importance case: “This underscores the importance of durable
execution.” Neither compact candidate supplies missing workflow facts. A permissible
response still asks what workflow state survives which failure, or recommends cutting
that unsupported importance claim. It must not invent a checkpoint, retry policy or
runbook. The compound addition only asks for resolution of an undefined supporting
label; the teaser addition only tests a promised payload. Neither licenses filling the
source gap. This is a manual rule-boundary check, not scored empirical evidence.
